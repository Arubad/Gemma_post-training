## 1. Leaderboard and baseline facts

### Takeaway

### Inferences
- The 15 distinct score values equal floor(k/58, 2 d.p.) for k = 0..14 exactly, and happyc0der writes "0.12 (7/58)": the public hidden split is 58 tasks (private ~62 of ~120). One task = ~0.017; +/-1 task is pure noise.
- With a 0.24 cap stable since early Oct and 0.22–0.24 reachable prompt-only, a realistic post-training target is 0.26–0.30 public (15–17/58); anything above that would be unprecedented on this LB.

### Gaps
- No official baseline per model size; no confirmed 12B LB score (12B startup problems, see §3); no E4B/E2B per-score table.

## 2. Organizer clarifications and rules details

### Takeaway
Tasks run sequentially under a 12 h wall clock (vLLM startup included, grading excluded); exceeding it currently errors the whole run (staff plan to score unfinished tasks as 0). Scorer reads only four `eval_config.yaml` fields; the evaluator compacts context at ~14,336 tokens; LoRA rank is uncapped but eats KV cache; distillation from external models is allowed if licences permit.

### Cited Findings
- Timeline/prizes: start 2026-09-23; Paper Track deadline 2026-11-12 23:59 UTC; entry/team-merge 2026-11-25; final 2026-12-02. Main $65k (37k/18k/10k), Paper $35k (15k/10k/10k), Small Model Bonus $10k; teams up to 5 — [reconscribe guide (transcribes Kaggle Overview/Rules)](https://reconscribe.com/gemma-4-developer-agent-competition-2026/); [Peoplerepabulic README](https://github.com/Peoplerepabulic/kaggle-gemma4-developer-agent).
- Allowed base models (exactly one, all agents/sub-agents): gemma-4-31b-it-qat-w4a16-ct, gemma-4-12b-it-qat-w4a16-ct (needs `--hf-overrides`), gemma-4-e4b-it-qat-w4a16-ct, gemma-4-e2b-it-qat-w4a16-ct — [reconscribe](https://reconscribe.com/gemma-4-developer-agent-competition-2026/).
- Hidden set: ~120 Python bug-fix/feature tasks from private repos, split public/private; each verified solvable (or within one test) by a larger frontier model; PASS/FAIL per task; ties to earlier submission — [reconscribe](https://reconscribe.com/gemma-4-developer-agent-competition-2026/). `test_patch` kept in `secret/solution.parquet` during scoring — [Kaggle data page snippet](https://www.kaggle.com/competitions/gemma-4-developer-agent/data).
- Concurrency: "Tasks run sequentially"; scorer reads only `timeout_seconds`, `max_tool_calls`, `max_time_minutes`, `max_turns` (unset = no limit); 12 h overrun = error now, planned = unfinished tasks score 0; staff advise a moderate `max_time_minutes` failsafe (thread 743063) — [PR #56 digest](https://github.com/emiliodavola/kaggle-gemma-agent/pull/56/files).
- Hardware: 4x L4 (96 GB), vLLM TP=4, gpu-util 0.80, `max_model_len` 32,768, thinking enabled, `gemma4` tool-call and reasoning parsers; L4x4 burns quota at 2x — [fatu/gemma4-dev-agent](https://github.com/fatu/gemma4-dev-agent); [reconscribe](https://reconscribe.com/gemma-4-developer-agent-competition-2026/).
- Compaction: hard ceiling 32,768 but evaluator compacts at `token_threshold` ~14,336; participant asked which applies, staff "will review" (thread 744692) — [PR #56](https://github.com/emiliodavola/kaggle-gemma-agent/pull/56/files). Contradicted by [happyc0der](https://github.com/happyc0der/gemma-swe-agent): "ADK never compacts context within a task, so trajectories die at the 32k window after ~20 full-size tool outputs."
- Thinking: `thinking_budget` and `seed` were not being sent — fixed; thoughts dropped between tool calls (vLLM ignored `reasoning_content`) — fixed, no rescore (744354); `include_thoughts` reportedly disables reasoning (745059, unofficial) — [PR #56](https://github.com/emiliodavola/kaggle-gemma-agent/pull/56/files).
- LoRA: PEFT folders with `adapter_config.json` + `adapter_model.safetensors`; different adapter per agent allowed, same base — [reconscribe](https://reconscribe.com/gemma-4-developer-agent-competition-2026/). With LoRA KV cache fell to ~7.6k tokens (46k without); rank-16 adapter later served 28k prompts on newer wheelhouse; official: vLLM now sizes LoRA buffers from the submission, so fewer/lower-rank adapters free KV — [discussion 744331 snippet](https://www.kaggle.com/competitions/gemma-4-developer-agent/discussion/744331); [PR #56](https://github.com/emiliodavola/kaggle-gemma-agent/pull/56/files). Rank 64 "scored" after OOM fix via `VLLM_MEMORY_PROFILER_ESTIMATE_CUDAGRAPHS=1` (749191) — [Utsav README](https://github.com/Utsav-X-bit/Gemma-4-Agent).
- Submission: `submission.zip` <= 3 GiB, `agent.yaml` at root, declarative ADK YAML; no `../`, symlinks, disallowed extensions; 1/day, 2 finals; 9 harness tools: run_command, submit_patch, get_status, read_file, edit_file, write_file, get_code_neighbors, search_similar_code, get_code_subgraph (+ run_skill_script/load_skill_resource for skills) — [reconscribe](https://reconscribe.com/gemma-4-developer-agent-competition-2026/). Calling an undeclared tool ends the task and discards the patch (745028) — [PR #56](https://github.com/emiliodavola/kaggle-gemma-agent/pull/56/files).
- Test-strip: test and runner-config hunks stripped from the patch; anything in `/workspace` enters the `git diff`, so scratch goes in `/tmp`; a non-empty source diff is graded even without `submit_patch` — [Utsav README](https://github.com/Utsav-X-bit/Gemma-4-Agent) (community reading of HARNESS_README).
- Distillation from external LLMs allowed if used under their licence (Ashley Oldacre, 742807) — [PR #56](https://github.com/emiliodavola/kaggle-gemma-agent/pull/56/files); contradicted by [reconscribe](https://reconscribe.com/gemma-4-developer-agent-competition-2026/) ("no official ruling as of 17 Oct").
- 12B: Ryan Holbrook posted `MODEL_VLLM_EXTRA_ARGS` with `--hf-overrides` setting architecture `Gemma4ForCausalLM`/model_type `gemma4`; scorer already has it; users still report `KeyError: vision_embedder.patch_dense.weight` on wheelhouse v30 — [discussion 748287 snippet](https://www.kaggle.com/competitions/gemma-4-developer-agent/discussion/748287).
- Small Model Bonus: $10k to highest private-LB submission whose base is E2B or E4B; must be one of the team's 2 selected finals; LoRA allowed; remains eligible for main prizes and Paper Track; daily standings notebook promised — [discussion 751104 snippet](https://www.kaggle.com/competitions/gemma-4-developer-agent/discussion/751104).
- Harness versions drifted: swegemma 0.2.7 / adk-submission 0.2.11 (released 09-25) -> swegemma 0.2.11 / adk-submission 0.2.12–0.2.13; wheelhouse v23 (adapter fix), 30-Sep wheelhouse (double-JSON fix), v30/v31 referenced; a rebuilt vLLM kept the same version number — [happyc0der](https://github.com/happyc0der/gemma-swe-agent); [fatu](https://github.com/fatu/gemma4-dev-agent); [pilkwangkim](https://pilkwangkim.github.io/posts/Gemma-4-Developer-Agent-Part-2-Measuring-an-Agent-While-Its-Evaluator-Moved/).

### Inferences
- Sequential scoring at ~58 tasks means your per-task budget can be ~10–11 min before the 12 h cap binds (happyc0der's full runs took 6.5–7.5 h at 5–8 min/task) — but if the private set is scored in the same run (~120 tasks), the budget is ~5.5 min/task. Treat 5 min/task as the safe ceiling until clarified.
- Whether thinking tokens count against `max_turns`/time: time yes (wall clock); no evidence they count against tool-call limits.

### Gaps
- Exact hidden repos; whether public+private are scored in one 12 h run; whether the 14,336 compaction applies on the scorer (open thread).

## 3. Known bugs / pitfalls

### Takeaway
The dominant failure modes are tool-call corruption (dropped calls before `</thought>`, missing `edit_file` args), repeat-call loops, 12 h/queue failures, LoRA adapters silently ignored or shrinking KV cache, and a local public task set that is not comparable to the scorer.

### Cited Findings
- "Scorer's vLLM 0.19.1 drops Gemma 4 tool calls emitted before the thought channel closes (MRE)" — thread by Smart Manoj on the [discussion index](https://www.kaggle.com/competitions/gemma-4-developer-agent/discussion) (ID not captured).
- 28.2% of `edit_file` calls in a 1,140-run corpus arrived missing a required argument; cause unlocalised between generation and parsing — [dp-pcs/gemma4-tool-call-reliability](https://github.com/dp-pcs/gemma4-tool-call-reliability). Related upstream: [vllm #44522](https://github.com/vllm-project/vllm/issues/44522), [#39392 (pad tokens under concurrency)](https://github.com/vllm-project/vllm/issues/39392), [#53431](https://github.com/vllm-project/vllm/issues/53431), [#38946](https://github.com/vllm-project/vllm/issues/38946).
- Repeat loops: after 3 identical calls, P(another) = 0.97; one 55-call loop hit 32k; missing string delimiter made the parser absorb text into a file path — [pilkwangkim](https://pilkwangkim.github.io/posts/Gemma-4-Developer-Agent-Part-2-Measuring-an-Agent-While-Its-Evaluator-Moved/). Temperature 0.2 produced 23 identical calls; model sent `submit_patch` to the shell — [happyc0der](https://github.com/happyc0der/gemma-swe-agent).
- Thinking on: 9/16 tasks hit session timeout (6/16 solved vs 13/33 off) — [happyc0der](https://github.com/happyc0der/gemma-swe-agent); 512-token thinking cap raised 5->7/22 and cut calls 57%, uncapped scored 0.05 vs capped 0.12 — [pilkwangkim](https://pilkwangkim.github.io/posts/Gemma-4-Developer-Agent-Part-2-Measuring-an-Agent-While-Its-Evaluator-Moved/).
- LoRA: adapters loaded but silently ignored ([vllm #41754](https://github.com/vllm-project/vllm/issues/41754); fixed wheelhouse v23); public PyPI vLLM says "does not support LoRA yet"; `discover_adapters` expects submission root; LoRA alpha/r = 2 (alpha 32, r 16) caused loops; first LoRA submission on ~1,500 trajectories scored 0.0 (750713) — [PR #56](https://github.com/emiliodavola/kaggle-gemma-agent/pull/56/files); [Utsav README](https://github.com/Utsav-X-bit/Gemma-4-Agent).
- Queue/timeouts: "Kaggle Error" pinned thread by Dustin; waits 14–33 h; "Notebook Exceeded Allowed Compute" at 12 h; one run blank after 54 h; "Notebook Timeout after 25h in queue" — [discussion index](https://www.kaggle.com/competitions/gemma-4-developer-agent/discussion); [happyc0der](https://github.com/happyc0der/gemma-swe-agent); [product-feedback 747611](https://www.kaggle.com/discussions/product-feedback/747611).
- Local eval mismatch: public wheelhouse lacks `typing_inspection`, `inline_snapshot`, `dirty_equals`, `python-multipart`, `pytest-httpbin`; Py3.13 `VERIFY_X509_STRICT` breaks ~8 requests tasks; gold patches pass 109/129 naively vs 127/129 calibrated (751487) — [PR #56](https://github.com/emiliodavola/kaggle-gemma-agent/pull/56/files); [happyc0der](https://github.com/happyc0der/gemma-swe-agent). Missing `pytest`/`pytest-timeout` in eval venv -> 0/5 — [fatu](https://github.com/fatu/gemma4-dev-agent).
- Graph tools: async functions absent (745998, host-confirmed); all edges are `calls`; 21.9% of embedding vectors are exact duplicates; `search_similar_code` accepts only symbol names and returns nothing for 57/129 issues; hit@5: embed 0.29, graph 0.30, grep 0.41, BM25 0.48, BM25-src 0.64 — [aghasalim/gemma4-code-graph-localization](https://github.com/aghasalim/gemma4-code-graph-localization); BM25 recall@20 69.0% vs best graph 53.3% — [HF dataset HIMANSHUKUMARJHA](https://huggingface.co/datasets/HIMANSHUKUMARJHA/gemma4-graph-retrieval-benchmark).
- `run_skill_script` with list `file_path` raises and ends task; sample budget (1 min/10 calls) yields `NO_PATCH`; Gemma bypasses skills for raw tools; scratch files leak into patches — [PR #56](https://github.com/emiliodavola/kaggle-gemma-agent/pull/56/files); [Utsav](https://github.com/Utsav-X-bit/Gemma-4-Agent); [CharlieHerbst331](https://github.com/CharlieHerbst331/gemma4-agent-lab).

### Inferences
- Disable or hard-cap thinking (<=512–2048), set temperature >0.2 with repeat-detection in the prompt, declare only used tools, and budget ~5 min/24–28 calls — this is the recipe the 0.22–0.24 cluster converges on.
